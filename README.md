# 墨迹 · 小说创作工作台

一个完全本地运行的写小说 Web 应用：**角色设定 → 大纲 → 章节大纲 → 正文** 的写作流，配合大模型对话、段落级 AI 改写、修改要求留痕与版本回退。角色与物品都可以挂上可自定义的**属性卡**，属性值随剧情成长并保留记录；角色还支持登场章节、死亡 / 失踪状态、技能，以及随章节变化的角色关系网；物品则有独立的来历设定与**状态时间线**。

- 前端：Vue 3 + Vite + TypeScript + Pinia
- 后端：Node.js（Express）
- 存储：SQLite（Node 22 内置 `node:sqlite`，无需安装数据库或原生编译依赖）

## 快速开始（单端口）

要求：Node.js ≥ 22（需要内置 `node:sqlite`）。

```bash
npm install   # 首次：安装前后端依赖（npm workspaces）
npm start     # 构建前端 + 启动服务，只有这一个地址
```

然后打开 **http://localhost:8787** —— 页面和 API 在同一个端口，不用再记 5173 / 8787 两个地址。

| 命令 | 作用 |
| --- | --- |
| `npm start` | **日常就用这个**：先把 `web/` 构建到 `web/dist`，再启动服务（API + 页面都在 8787） |
| `npm run serve` | 只启动服务，用现成的 `web/dist`（改完代码没重新构建时不要用） |
| `npm run build` | 只构建前端到 `web/dist` |
| `npm run check` | `vue-tsc` 类型检查 |
| `npm run dev:hot` | 仅在改前端代码时用：Vite 热更新跑在 5173，API 在 8787（两个端口） |

**改了代码却没生效？** 99% 是没重新构建。执行 `npm start`（会自动构建），或 `npm run build` 后重启服务。想确认自己看的是不是最新版本：打开右上角 **⚙ 设置**，弹窗左下角会显示「构建于 2026-11-06 11:02:31」这样的构建时间。

首次启动会自动创建 `server/data/novel.db` 并写入 DeepSeek / OpenAI / Ollama 三个服务商预设。

## 配置大模型

进入右上角 **⚙ 设置**：

1. 选择服务商预设（DeepSeek / OpenAI / Kimi / 智谱 / 硅基流动 / Ollama / 自定义），填写 Base URL 与 API Key；
2. 点「测试连接」或「拉取模型列表」验证可用性（Ollama 等本地服务 Key 可留空）；
3. 添加模型名称（如 `deepseek-chat`），可设置温度、最大 tokens、默认模型；
4. 顶栏、对话栏、精修弹窗都可以随时切换当前模型。

后端以 OpenAI 兼容接口请求模型，API Key 只保存在本地 SQLite，不会暴露给浏览器端请求。

### 本地 Ollama

- Base URL 填 `http://localhost:11434/v1`（必须带 `/v1`），API Key 留空或随便填一个占位值；
- 模型名要与 `ollama list` 中的名称一致（例如 `lfm3:latest`），先确认 `ollama serve` 正在运行；
- 使用带思考过程的模型时，对话栏会先显示「模型思考中…」的思考内容，再流式输出正式回复；
- 如果对话长时间没有任何输出，先看服务端日志与对话栏红色错误提示，再用 `ollama run <模型>` 确认模型本身能正常回答。

## 使用流程

1. **写角色**：左侧「角色」为每个角色维护基本档案（定位、性别、年龄、登场、外貌、背景、目标），并把性格拆成多个「阶段」；还能记录技能、死亡 / 失踪状态，以及和其他所有角色的关系变化；角色页会按「当前持有人」自动列出身上的物品。
2. **定大纲**：左侧「大纲」树支持一级条目与子条目（故事主线、世界观、人物小传……），随时可改。
3. **写章节**：左侧「章节」合并了章节大纲与正文列表，点击后在同一页里规划情节节拍、再逐段写正文。
4. **记物品**：左侧「物品」为武器、信物、关键道具维护来历与流转，设定卡与状态记录分成两个标签页。
5. **设计属性卡**：左侧「模板」页分别设计人物 / 物品卡片上有哪些属性，角色页与物品页会立刻采用。
6. **看总览**：顶部「总览」按「章节 × 人物」展开矩阵，一眼看到每个人在任意章节是否登场、状态、阶段、属性、技能和随身物品。

左侧区域用五个页签（大纲 / 角色 / 物品 / 章节 / 模板）切换，一次只展示一类内容；上方是 VS Code 风格的多文档页签，可以同时打开总览、多个章节、角色、物品和模板页，随时点页签切换、点 ✕ 或鼠标中键关闭。

章节列表超过 10 章会自动出现分页器，默认每页 20 章，可切换 10 / 20 / 50 / 100，也支持直接选择页码；搜索跳转到某一章时会自动翻到它所在的页，几百章也能快速定位。

### 角色与分阶段性格

角色的性格不是一成不变的。一个角色可以有多个「性格阶段」，例如「十年前 · 妹妹 → 第 1-6 章 · 记录者 → 第 12 章起 · 涉水者」：

- 每个阶段可以填写 **阶段名、生效范围（如「第 1-5 章」）、关联章节、性格特点、内心动机、行为表现、语言习惯、关键事件/转折点**；关联章节用于人物总览从准确的章节开始展示该阶段；
- 任意阶段可「设为当前」；当前阶段会显示在侧栏，并默认注入 AI 上下文；
- 角色编辑与阶段调整前后都会参与版本快照，可对比、恢复；
- 对话栏与精修弹窗都可以选择是否附带「角色设定」；**附带时按当前打开的章节解析**：只看该章已登场的角色（依据角色页的「登场」），每人取「该章及之前最近一个生效的阶段」，不会把第 51 章的性格写进第 5 章；
- 精修弹窗占 96vw × 92vh，是**三栏并排**的：左＝修改要求与勾选、中＝修改预览、右＝上下文。不用在「上下文 / 修改预览」之间来回切，边上改要求边能看上下文；
- 上下文栏默认展开，点「收起右侧上下文」可让修改预览占满剩余宽度；这一栏独立滚动，展开很长的角色设定也不会把弹窗撑破；
- 上下文栏里，**上面勾了什么，左边就有什么条目**（角色设定 / 全书大纲 / 章节大纲 / 本章正文 / 选中文字 / 前文 / 后文），每条标着字数，点开就是真正会发给模型的原文，右上角可「复制这段」；角色设定那条逐人列出被选中的阶段、生效依据（从第 N 章起生效 / 没有按章节拆分 / 角色卡当前标的是哪个阶段）与被略过的未登场角色，**点人名可就地展开这个人的完整设定**，也能在「按人查看 / 原始文本」之间切换；
- 「附带角色设定」下面还有三个小勾：**属性 / 技能 / 随身物品**，各自控制要不要把「该章」的快照写进上下文。写打斗、受伤、用道具的段落时打开；日常过场关掉，省 token 也不会让 AI 一直盯着数值写；
- 取消勾选某一项后，对应条目会立刻消失，不会出现「取消了却还在发」的情况；
- 对话栏点「已附带…查看」会在对话栏内切换到同一套上下文面板（面板打开时对话栏自动加宽到 500px），按 Esc 或「返回对话」回到聊天，不遮挡、不跳页；
- 没有打开章节时（例如续写大纲条目），退回使用各角色角色卡上的「当前阶段」，预览里会标明；
- 角色页顶部按功能分成 **基本档案 / 属性卡 / 持有物品 / 技能 / 状态 / 关系网 / 性格成长 / 全部** 八个板块页签，默认只看基本档案；选「全部」即可恢复原来的长页面，切换板块后自动回到顶部。
- 每个角色会记住自己上次选中的板块：林岚停在「持有物品」时切去老周，再切回林岚仍停在「持有物品」；刷新页面后也会保留。

### 人物状态、技能与关系网

- 基本档案新增 **性别、登场时间描述、登场章节**；设了登场章节后，人物总览在这一章之前会显示「未登场」；
- 「状态」板块可以按章节记录 **存活 / 死亡 / 失踪 / 未知**，并填写时间与原因；总览会回溯出每一章的状态；
- 「技能」板块支持增删和自动保存，每个技能可写名称、等级 / 熟练度、说明和获得章节；
- 「关系网」列出这个角色与其他所有角色之间的关系，可选 **陌生 / 认识 / 友善 / 合作 / 亲密 / 对立 / 敌对 / 亲情 / 爱情 / 师徒 / 利用 / 其他**，并指定从哪一章生效、填写变化原因；
- 关系按「一对角色」存储：从任何一方记录，双方看到的都是同一条当前关系；多次记录会形成时间线，总览与角色页取该章节最新的关系。

正文中使用方式：

- **选中文字** → 出现浮动按钮：`✦ AI 修改` / `在对话中问` / `复制`；
- `AI 修改` 会打开精修弹窗：填写修改要求、勾选上下文、流式生成、对比修改前后、确认应用；
- **Shift + 点击段号** 可多选连续段落，批量交给 AI；
- 左侧搜索框可同时搜索**章节标题、章节大纲、正文全文**（防抖 + 关键词高亮 + 命中片段），从正文结果进入章节时会自动滚动并高亮命中的段落；
- 修改后的 **修改要求** 会保留在段落下方（可在工具栏「修改要求」开关显示），同时汇总到章节的「修改记录」抽屉。

### 属性卡模板与属性成长

- 每个作品有**一套人物属性卡**和**一套物品属性卡**，在左侧「属性卡模板」里自由设计；
- 每个属性可选类型：文本 / 数值 / 长文本 / 选项（选项用逗号分隔，填写时变成下拉框），并可以设置单位；
- 属性字段支持重命名、改类型、上移 / 下移、删除；改动会自动保存，所有角色 / 物品立即采用新结构；
- 角色页与物品页的「当前属性」直接编辑，失焦后 700ms 防抖自动保存；
- 「记录成长」会写入一条成长记录（变化后的值、时间/章节、**关联章节**、原因说明），可选择**同时更新当前属性值**；关联章节让总览能准确回溯该章时的属性；
- 成长记录保留历史，删除记录不会让当前属性值回退，方便表现「属性随剧情推进逐步成长」；
- 删除模板字段会级联删除对应的属性值与成长记录（操作前会二次确认）。

### 物品与状态记录

物品页分「设定卡」与「状态记录」两个标签页：

- 设定卡：名称、类别、稀有度、来源、登场时间、出现的原因、背景故事、补充备注，以及物品属性卡；
- 状态记录：
  - 当前状态可直接修正：状态（完好 / 遗失 / 封存 / 已损毁 / 下落不明）、当前持有人、是否被摧毁、摧毁者、摧毁时间/章节；
  - 新增状态记录时可填写时间/章节、**关联章节**、持有人、状态、摧毁者、说明，并可勾选「同步更新物品当前状态」；关联章节决定总览里这件物品从哪一章开始易手；
  - 状态时间线按记录顺序展示全部流转，历史持有人从所有记录中去重汇总，当前持有人单独标记；
  - 删除状态记录不会让物品当前状态回退。

### 人物总览

顶部「总览」按钮会打开一张 **章节 × 人物** 的状态矩阵：

- 横轴按章节顺序排列，可选起止章节只看某一段剧情；
- 纵轴是人物，点击人名筛选显示 / 隐藏，支持全选、全不选，筛选结果会记住；
- 单元格显示该人物在这一章是否已登场、性格阶段、存活 / 死亡 / 失踪状态、当时的属性数值、已获得的技能，以及身上携带的物品；
- 阶段取「该章及之前最近的一条」，属性按成长记录回溯，状态按状态记录回溯，技能按获得章节筛选，物品按状态时间线回溯；没有状态记录的物品默认从头到尾都在当前持有人身上；
- 老数据没有「关联章节」时，会从「第 3 章」「第三章」「1-5 章」这类文字里自动解析章节序号；
- 尚未登场的人物，单元格直接显示「未登场（第 N 章登场）」；登场章节取角色页的「登场」，没有显式关联时也会从文字里解析，都为空则视为从第一章起在场；
- **同一个角色连续几章状态没变时，会合并成一格**并标出「第 1-25 章」这样的范围，不会把同一张卡重复画 50 遍；
- **状态发生变化的那一章开头会出现「⇄ 对比」**，点开可以看这一章前后的差异：性格阶段、章节状态、属性（只列变化的）、技能（＋新增 / －消失）、随身物品（新增 / 不再持有 / 状态变化）；「未登场 → 登场」会显示成一次「首次登场」；
- **点任意格子，右侧会弹出该章的角卡**：章节名、人物的章节状态、该章生效的性格阶段（含性格特点 / 内心动机 / 行为表现 / 语言习惯 / 关键事件）、该章属性值、该章可用技能、该章随身物品、本章大纲，以及可折叠的角色档案；再点另一格会直接切换到那一章，按 Esc 或 ✕ 关闭；
- 点击人名打开角色页，点击物品打开物品页。

### 自动保存

除「新增记录 / 删除」这类显式提交外，所有文本与属性值编辑都会自动保存：

- 段落、大纲、章节标题/大纲、角色档案、性格阶段、物品字段、模板字段、属性值均为 700ms 防抖保存；
- 顶栏会显示「保存中 / 已保存 / 保存失败」状态；
- 切换角色 / 物品 / 章节、打开历史版本、退出页面前会先冲刷所有待保存内容，避免丢失；
- 对话与 AI 改写产生的修改会在应用前先保存当前内容，并可回退。

## 版本控制

- 手动保存：章节/大纲/角色编辑器里的「历史版本」
- 自动快照：编辑正文/大纲/角色时约 2 分钟节流一次，去重保存
- AI 修改前、恢复版本前，服务端都会自动生成快照
- 「历史版本」支持与当前内容做逐字/逐行 diff 对比、恢复、删除；恢复前会自动备份当前状态

版本快照以 JSON 存在 SQLite 的 `versions` 表中，章节、大纲与角色分开管理。

## 主要 API

- `POST /api/chat/stream`：SSE 流式转发模型输出（前端不接触 Key）
- `GET /api/characters?projectId=`：角色列表（含全部性格阶段）
- `POST /api/characters` / `PATCH /api/characters/:id`：新建 / 更新角色基本档案（含性别、登场时间、登场章节）
- `POST /api/characters/:id/stages` / `PATCH /api/character-stages/:id`：新增 / 更新性格阶段
- `POST /api/characters/:id/current-stage`：切换当前阶段
- `POST /api/characters/:id/skills` / `PATCH /api/character-skills/:id` / `DELETE /api/character-skills/:id`：新增 / 更新 / 删除角色技能
- `POST /api/characters/:id/status-logs` / `DELETE /api/character-status-logs/:id`：记录 / 删除角色状态（存活 / 死亡 / 失踪 / 未知）
- `POST /api/characters/:id/relations` / `DELETE /api/character-relations/:id`：记录 / 删除角色与其他角色的关系及生效章节
- `GET /api/card-templates?projectId=`：人物 / 物品属性卡模板（含字段，首次访问自动创建默认模板）
- `PATCH /api/card-templates/:id` / `POST /api/card-templates/:id/fields` / `PATCH /api/card-fields/:id`：改模板、加字段、改字段
- `DELETE /api/card-fields/:id` / `POST /api/card-templates/:id/fields/reorder`：删字段、字段排序
- `GET /api/attributes?entityType=&entityId=`：对象的当前属性值与成长记录
- `PUT /api/attributes` / `POST /api/attribute-logs`：保存当前属性值、记录一次成长（可同步当前值）
- `GET /api/items?projectId=` / `POST /api/items` / `GET /api/items/:id`：物品列表、新建、详情（含状态记录与历史持有人）
- `PATCH /api/items/:id` / `DELETE /api/items/:id`：更新物品字段、删除物品
- `POST /api/items/:id/events` / `PATCH /api/item-events/:id` / `DELETE /api/item-events/:id`：新增 / 更新 / 删除状态记录（可选同步当前状态）
- `GET /api/overview?projectId=`：人物总览矩阵（章节列 × 人物行，含是否登场、状态、阶段、属性数值、技能与随身物品）
- `GET /api/chapters/search?projectId=&q=`：章节搜索（标题 / 章节大纲 / 正文，返回命中字段、片段与段落 id）
- `POST /api/revisions/apply`：应用改写（`block` / `chapter-summary` / `outline` / `append`），同时写入修改要求
- `GET /api/chapters/:id/revisions`：章节修改记录汇总
- `GET /api/versions?targetType=&targetId=` / `POST /api/versions/:id/restore`：版本列表与回退
- `POST /api/providers/:id/test` / `POST /api/providers/:id/remote-models`：连接测试与拉取模型
